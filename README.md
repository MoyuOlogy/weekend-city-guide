# 🧭 周末探索 · 周末城市探索指南

一个面向大学生的周末城市探索指南：根据 **偏好 · 天气 · 预算 · 同行人数** 推荐本地活动，支持 **组队出发、打卡记录、攻略分享**，并能在 **多台设备之间同步**。

🔗 在线访问：**https://moyuology.github.io/weekend-city-guide/**

---

## ✨ 功能

### 🔍 推荐引擎（可解释加权评分）
- 城市（8 城）、周六/周日、人均预算、同行人数、可支配时长、10 类活动多选、额外偏好（近 / 省 / 出片 / 新手友好）
- 每条推荐都给出 **匹配度 %** 和 **推荐理由 / 风险提示**（如「命中偏好 · 桌游」「¥45 在预算内」「超预算 ¥30」「至少 2 人」），而不是黑箱排序

### 🌤 天气联动
- 接 **Open-Meteo** 真实预报（免费无 Key），按「即将到来的那个周六/周日」精确取当天数据（`forecast_days=7`）
- 首页天气条是一条**紧凑胶囊条**（不是几个大白块）：`📍城市 | 周六 9/19 15~24° | 周日 9/20 15~21° | 距周末 3 天 · 距「中秋节」9 天 | ☔ 优先室内 | 🔔 调休上班`，全部等高内联、没有多余留白
- 实测高度：**1280px 单行 40px / 731px 两行 74px / 375px 三行 100px**（这项有断言守着预算，改胖了会红）
- 雨天自动把户外活动降权、优先室内；断网自动降级为示例天气并明确标注

### 📅 假期（日历 · 调休 · 天气提醒）
**设计目标：一进这个页面就把日历 / 天气 / 假期提醒全看完，不用往下滚。**
- 月历按**周一起始**，标出 **周末 / 法定假期 / 调休上班 / 今天**，配色与图例一一对应
- 日历格子里直接带上**未来 7 天天气预报**（Open-Meteo 覆盖范围内的日期才显示）
- 顶部提醒是**一行内联胶囊**（不是一叠整行大色块）：近期**调休上班**日期、距离**下一个假期**还有多少天、周末两天的气温与出行建议 —— 长尾信息（天气描述、降水概率、假期起止）收进悬停提示
- 下方全年**放假安排**是**两列紧凑列表**（每行一个假期：日期 / 天数 / 调休），不是 7 张上下堆的卡片
- 上/下月切换 + 「回到今天」
- 为了让上面这些塞进一屏，专门压缩了间距与格子高度：提醒从 4×44px 变成 1×28px、格子从 66px 压到 44px、放假安排从 7 张卡变成 4 行。**布局测试里有一条断言直接量「最后一个内容的底部是否在视口内」**，超过了就红。

### 👥 组队 / 📍 打卡 / 📝 攻略
- 组队：建队、加入退出、满员进度环、一键复制邀请文案、发起人可解散
- 打卡：地点 / 日期 / 花费 / 时长 / 心情 / 感想，自动统计次数·总时长·总花费·去过的地点数
- 攻略：发布、标签、点赞、复制；攻略标签可点，点了直接跳首页按该标签筛选
- 还能 **自建活动** 加入活动库，房间内共享

### 🌐 跨设备同步（v2 新增，重点）
三种方式，互为兜底：

| 方式 | 机制 | 适用 |
| --- | --- | --- |
| **云端房间** | 6 位房间码 → `textdb.dev` 上的一个 JSON 文档；页面每 6 秒轮询合并，改动后 0.6 秒自动上传 | 手机建队，电脑/同学立刻看到 |
| **分享链接** | 把数据打包进网址 `#r=...`，任何设备打开即导入 | 一次性发给同学，永久有效、不依赖第三方服务 |
| **导入 / 导出 JSON** | 本地文件备份 | 换机迁移、留档 |

同步不是简单的「整份覆盖」，而是：

- **发布前先拉取合并**（read-modify-write），避免后写的客户端用较少的数据抹掉别人的贡献
- 按 `id` 求并集 + 同 `id` 取 `ts` 较新者；**墓碑机制**保证删除不会被旧快照复活
- 点赞按「每人最后一次操作生效」（`{昵称: ±时间戳}`），既不会把取消赞刷回来，多人点赞也能正确累加
- 失败自动降级：网络不通时数据只存本机，界面明确显示 🔴 同步失败，不会丢数据

- 交互：点赞心跳、滚动入场动画、骨架屏、触感反馈、分类实时筛选与搜索
- **配色禁用蓝紫**：全站仅用红 / 橙 / 黄 / 橄榄绿 + 暖中性色（浅色与深色两套主题，默认浅色）。这项有自动化色相断言守着

### 🧭 关于页 = 新手指引 + 项目说明

「关于」页里有**两块内容**，顶部两个标签切换：

**① 新手指引（新手第一次来会看到这块）**

- **第一次访问网站会强制弹出一遍逐步引导**：全屏遮罩 + 在目标元素周围挖一个高亮框，旁边跟一张说明卡，一步步告诉你天气条、分类筛选、推荐卡片、组队、打卡、攻略、假期页、我的页分别在哪、能干什么

**② 项目说明（就是这份 README 的内容）**

功能清单、怎么用跨设备同步、技术栈与数据来源、质量验证、已知限制、仓库地址。排版刻意**不做成文档流**（`h2` + 一大段 `p` + 一长串 `ul` 那种读起来很累的形态），而是块状：顶部一张 hero 卡放标题、一句话简介和两个入口按钮；下面每节一个带红色竖条的小标题，功能是**两列卡片网格**（每条一句话），技术栈 / 同步方式是**条目式**。

> 默认落在哪个标签：**没看过引导 → 新手指引；看过（或刚走完强制引导）→ 项目说明**。这条规则写在 `endTour()` 与 `renderAbout()` 里，有断言守着。
> 引导的技术细节：高亮靠一个 `position:fixed` 的方块 + `box-shadow: 0 0 0 9999px rgba(...)` 把周围压暗（不额外铺一层背景）；目标比视口还大时只圈住可见部分；说明卡按「目标下方 → 上方 → 居中」依次尝试，并夹在视口内。引导期间锁滚动，避免用户滑走之后高亮框和内容对不上。

## 🛠 技术栈

原生 HTML + CSS + JavaScript，**零依赖、零构建**，GitHub Pages 静态托管。数据存 `localStorage`（v1 数据自动迁移）。

### 文件结构

```text
index.html               骨架 + <link>/<script> 引用（约 320 行）
assets/css/
  base.css               变量 / reset / 排版 / 通用工具类
  layout.css             桌面左侧栏 / 顶栏 / 分类条 / 底部 Tab / 悬浮发布
  components.css         天气条 / 工具行 / 瀑布流卡片 / 列表 / 表单 / 弹层
  pages.css              假期 / 关于
  tour.css               新手引导：关于页的标签页与步骤列表 + 全屏引导遮罩
assets/js/               21 个模块，与原代码里的注释模块一一对应
  util · store · data · weather · recommend · cover · feed · sheet · filter
  publish · team · checkin · guide · me · calendar · router · tour
  sync · events · io · init
tests/                   开发期验证工具（不参与部署）
```

**为什么拆、为什么是这种拆法**

v2.6 之前全站是一个 2192 行的 `index.html`。拆分的依据不是「大概这么分合适」，而是**代码里本来就写好的 19 个注释模块边界** —— 每个 js 文件都是原来那一块的**搬运**，不是重写，所以拆分本身不引入行为变化。

拆分后有个硬约束必须守住：**全站不能用 ES module**。GitHub Pages 本身支持任意文件类型（官方支持 750+ 种 MIME 类型，不能做的只有服务端语言 PHP/Ruby/Python），但 `file://` 直接双击打开时 `<script type="module">` 会被 CORS 挡掉、整段不执行。所以采用**经典 `<script defer>` 按依赖顺序加载**（`defer` 保证在 DOM 解析完、并按文档顺序执行），这样「双击 `index.html` 就能跑」这个承诺依然成立。

同理有两条容易踩的坑，改动前务必知道：

| 特性 | `file://` 双击打开 | 本地 http 服务 / 线上 |
| --- | --- | --- |
| `<link>` CSS、经典 `<script src>` | ✅ | ✅ |
| `<script type="module">` | ❌ 被 CORS 挡 | ✅ |
| 外链 SVG sprite（`<use href="x.svg#id">`） | ❌ 渲染为空 | ✅ |
| 在 JS 里读 `styleSheets[i].cssRules` | ❌ SecurityError（样式仍生效） | ✅ |

因此**图标 sprite 继续内联在 `index.html` 里**（一共 25 个 symbol，本来也不大）。另外测试脚本带了 `--allow-file-access-from-files`，所以上面这些在测试里是通的 —— 这正是「测试全绿但用户双击打开白屏」的经典陷阱，**新增依赖 module 或外链资源的写法，必须单独确认无参数 `file://` 下的行为**。

还有一个只在部署后才暴露的坑：GitHub Pages 跑在 Linux 上，**文件名大小写敏感**，而 Windows 本地不敏感。`Components.css` 写成 `components.css` 会「本地好好的、线上 404」。

**拆分重构的等价性证据**（v2.7 把单文件拆成 `index.html` + `assets/*`）：除了上面 257 项断言全绿，还额外做了「结构指纹」比对 —— 拆之前和拆之后各跑一遍页面，把**渲染结果**导出成可比对的形式（968/990 个元素的 `tag#id.class` 结构 + 40 多个关键元素 × 27 个 CSS 计算属性 + 13 项元素计数），然后 diff：

- **计算样式段逐字节一致** —— 没有 CSS 级联顺序问题
- **13 项计数全同**（卡片 16 / 日历格 35 / 假期卡 7 / 底栏 5 格 / 侧栏 10 项 / 图标 symbol 25 个 ……）
- 唯一的差异就是预期的记账项：`<link>` 从 1 个变 4 个、`<script>` 从 1 个变 20 个

再加一测：**不加任何浏览器参数直接以 `file://` 打开**，`body` 算出的颜色是 `rgb(51,51,51)`（= 我们 CSS 里的 `#333`，没有 CSS 会是纯黑）、`rail` 的媒体查询生效 —— 证明「双击打开」这条路径样式和脚本都是真的好使，不是「结构出来了但样式全丢」。

每个套件的完整输出会留在 `tests/_logs/*.txt`（UTF-8），失败时直接翻日志即可。

开发过程中被这套测试抓出并修掉的真实缺陷：

1. `forecast_days=3` 导致「本周六」显示的是周三天气
2. 降水判定口径不一致，出现「降水概率 39%」却提示「☔ 有降水」
3. `toISOString` 在 UTC+8 晚间会跨天
4. **发布整份覆盖会抹掉同伴数据** → 改为读-改-写
5. **`Accept: application/json` 让 textdb 把响应再包一层 JSON 字符串**，导致合并静默失效（只有真实端到端测试才能发现）
6. ntfy.sh 免费版每日消息配额（实测触发 HTTP 429）→ 换成 textdb.dev
7. **分类条放在矮的静态 header 里导致永远吸不住顶** —— `position:sticky` 被限制在父容器范围内，必须与搜索栏同处一个 sticky 容器
8. **卡片可见性绑在动画上**（`opacity:0` 等 JS 加类才显形）→ 动画没跑整页就是空白。改为「默认可见 + 动画只做增强」，并支持 `prefers-reduced-motion`
9. **「双击点赞」把桌面点击劫持了**：卡片原来用「240ms 延迟 + 双击点赞」，桌面用户点一下没反应就会再点一下 → 被判成双击 → 变成点赞、**详情永远打不开**。改成：封面/标题是真链接、桌面点击**立即**打开详情、双击点赞只在触屏启用（用真实鼠标事件序列的测试守住）
10. **`await navigator.clipboard` 挡住了 UI**：「生成分享链接」先 await 复制、再渲染面板；剪贴板被权限/无焦点阻塞时 await 不返回，用户看到的是「点了没反应」。改成**先渲染面板再尝试复制**
11. **攻略卡片里的「点赞 / 复制」是死按钮**：全局点击处理里有一段「认识之外的 `.chip` 一律吞掉并 `return`」，标签 chip 和按钮共用同一片区域，于是点击被半路截胡。改成**只处理认识的 chip 组，其余交回给 `[data-act]` 继续分发**，并给攻略标签 chip 补上「点标签 → 跳首页按标签筛选」的真实行为
12. **天气条改版时把城市名弄丢了**：换成「周六 + 周日两张卡 + 倒计时」后，原来那行 `上海 · …` 没了 —— 行为测试里「天气条渲染出城市」当场变红，补回城市与出行建议
13. **底部 Tab 加成 6 格后在 375px 下挤爆**：`repeat(6,1fr)` 让每格只剩 62px，标签开始挤。回到 **5 格**，把「日历 / 关于」移进「我的 → 更多」，并在停在子页面时把底部高亮改为「我的」
14. **测试脚本用 PowerShell 管道抓浏览器输出**：管道按控制台代码页（中文 Windows 是 CP936）解码浏览器输出的 UTF-8 字节，日志里中文全成乱码、`★` 这类字符直接丢失 —— 表现成「行为测试和布局测试没有任何输出」，看起来像套件没跑。改成 `ProcessStartInfo` + `StandardOutputEncoding = UTF-8` 显式按 UTF-8 读，并把每个套件的输出落盘到 `tests/_logs/`
15. **拆文件把颜色审计拆成了空转**：v2.7 把样式搬进 `assets/css/` 之后，`color-audit.js` 还在只读 `index.html` —— 于是它扫了个寂寞却照样打印「✅ 通过」。**静默失效的测试比没有测试更危险**。修法：递归扫描 + 断言「文件数 / 颜色数不低于下限」，并实测验证过「把 css 目录改名后审计会立刻报错」，确保守卫不是摆设
16. **测试注入页的位置和相对路径耦合**：`index.html` 用相对路径引 `assets/*`，而测试脚本原先把注入页写在 `tests/` 下 → 拆分后所有资源 404（页面结构对、样式全丢）。改成把注入页写在**仓库根目录**，同时把布局测试里的 iframe `src` 从 `../index.html` 改成 `./index.html`
17. **点赞断言是「看天吃饭」的脆弱断言**：它固定拿**信息流第一张卡**，断言「点一下计数 +1」。但排序由天气评分决定（天气预报一变，首卡就换），而示例数据预先把 `a2/a6/a9` 标成「已赞」—— 首卡正好是其中之一时，第一次点击是**取消赞**、计数 -1，断言就红了。而当时 `点赞写入 localStorage`、`再次点击取消赞` 都是通过的，说明**产品没问题、是断言写错了**。改成「显式挑一张没赞过的卡」+「断言状态必须翻转、计数变化 ±1」，不再依赖数据顺序
18. **天气条与日历页「太空」**：原来的天气条是两个大白块 + 一列文字，留白大、颜色也和主题不搭；日历页的 4 条提醒是整行大色块、还跟着 7 张放假安排卡片，一进页面就得往下滚。改成：天气条 → 淡红底紧凑胶囊条（实测 1280px 单行 40px / 375px 三行 100px）；提醒 → 一行内联胶囊（每个 28px）；日历格子 66→44px；放假安排 → 两列紧凑列表。**净省下约 350px，1280×820 一屏看完**，并加了断言守着这个预算
19. **关于页读起来累**：原来是 `h2` + 一大段 `p` + 一长串 `ul` 的文档流，密且难扫读。改成块状：hero 卡 + 带竖条的小标题 + 功能两列卡片网格 + 条目式技术栈
20. **强制弹出的新手引导把整套测试挡住了**：v2.9 加完引导后，凡是点 DOM 的断言全红 —— 测试每次都用全新 profile，等价于「第一次访问」，遮罩一直盖着。这暴露的是**测试环境与真实使用状态不一致**。正确做法不是「在测试里让产品不弹」，而是**先断言它确实弹出来了，再关掉**：既恢复了后面的断言，又顺带覆盖了新功能。另外实测确认：同源的 iframe 会共享 `localStorage`，所以外层页面关掉引导之后，布局测试里的 iframe 不会再弹
21. **「关于」页的默认标签没跟着跳**：初始加载时按「没看过引导」把标签设成「新手指引」，可是用户跳过引导时人在首页，「关于」页还没打开 —— 这个选择就被保留下来了，之后进关于页看到的还是引导面板，跟「看完引导就显示说明」的约定不符。断言直接抓到了它（「看过引导后进关于页应显示项目说明」）。修法：`endTour()` 里无条件把标签落到「项目说明」，但**用户自己在引导面板点开的重放不抢标签**
22. **隐藏面板里的元素量出来全是 0**：断言「步骤列表在手机上是单列」时面板还是 `hidden`，于是每个 `.gstep` 的 rect 都是 0、`top` 全相同 —— 单列那条**假红**、两列那条**假过**（`rows.size < items.length` 被 0 满足了）。断言前先切到那个面板，并校验元素真的可见（`width > 0`），否则就是在量空气

### 测试踩坑（值得记下来）

- **Windows 无头窗口有最小宽度**：`--window-size=390` 时实际布局视口是 **503px**，截图只是把 503 裁成 390 —— 一度让我误判"右列被挤出屏幕"。改用 iframe 强制精确视口后，量到 `body.scrollWidth == clientWidth`，确认根本没有横向溢出。**结论：先用数值诊断（`scrollWidth` / `getBoundingClientRect`）确认，再动手改样式。**
- **无头虚拟时钟不驱动 CSS 动画/过渡**：属性会永远停在起始值——`animation ... both` 的卡片一直 `opacity:0`，弹窗的 `transform` 一直等于关闭态，截图看着像"没渲染"、量坐标得到的是关闭位置。对策：截图用 `--force-prefers-reduced-motion`（顺带验证无障碍降级分支），布局测试则注入 `*{transition:none!important;animation:none!important}`，让最终布局立即生效。**注意：别为了"好测"去改产品代码（比如去掉过渡），要在测试侧消除不确定性。**
- **`100vw` 包含滚动条宽度，`100%` 不包含**：弹窗用 `width:calc(100vw - 24px)` 会被滚动条挤住（375 的 iframe 里实测 `100vw=375` 而 `clientWidth=360`，弹窗压到滚动条下面）。`position:fixed` 的包含块就是不含滚动条的视口，所以改用 `calc(100% - 24px)` 才对。
- **父子样式互相夹住**：基础 `.sheet` 上的 `max-width:600px` 会把 `#sheetDetail` 的 880px 一起夹住（ID 选择器能覆盖 `width`，但覆盖不了另一条规则里的 `max-width`）。分端尺寸改成各档显式 `width`，不用 `max-width`。
- **`--screenshot` 在页面 load 就抓拍了**：想「注入一段脚本切到我的页再截图」，结果每个页面截出来字节数完全一样（都是首页）—— 注入的 `setTimeout` 根本还没轮到跑。而且 DOM dump 明明是 `vis=page-me`、`tabs=5`，说明产品没问题、是截图时机不对。对策：**把初始 `hidden` / `on` 状态直接改好再截**，首帧就是目标页，确定性最好；要精确视口就再用一层 iframe 包住（否则又踩回「无头窗口最小宽度 503px」那个坑）。
- **别用「字节数一样」当成"没生效"的唯一判据，也别用「刚才看过这张图」当成没变化**：截图工具与图片缓存都可能在骗你。**用 DOM dump + 断言去验证状态，截图只用来看观感。**
- **含中文的 `.ps1` 必须带 UTF-8 BOM**：Windows PowerShell 5.1 对**没有 BOM** 的 `.ps1` 按 ANSI/CP936 解码。`run-tests.ps1` 里那句 `$_ -match 'TESTS|^FAIL|★'` 的 `★`（UTF-8 `E2 98 85`）会被解成垃圾字节、引号提前终止，报「字符串缺少终止符」+「缺少右 }」—— 看着像引号写错了，实际整份脚本一行都没跑。用编辑器/脚本新写这个文件时记得保留开头的 `EF BB BF`（`pwsh` 7 不受影响，但别假设别人的机器有）。
- **诊断信息一律落盘再看**：把脚本的 stdout 再接一层 PowerShell 会把乱码带回来（外层仍按自己的代码页解码子进程输出）。`tests/_logs/*.txt` 才是可靠通道，控制台输出只是尽力而为。
- **别让断言依赖「第一条数据」**：点赞那条断言吃了这个亏 —— 列表顺序由**天气评分**决定（天气一变首卡就换），而首卡可能已经被示例数据标成「已赞」，于是「+1」变成了「-1」。**凡是结果依赖排序或初始状态的断言，都要先显式选出一条符合前提的数据，或者断言「状态必须变化」而不是「变化的方向和幅度」。** 顺带一个判断技巧：如果同一片区域的**其他断言都通过**、只有某一条红，先怀疑断言写错了，再怀疑产品坏了。
- **过渡卡住的不只是截图，还有「引导高亮框的位置」**：写引导的探针时，量到的高亮框位置连着 4 步都一模一样 —— 因为 `--virtual-time-budget` 下 CSS transition 不推进，`left/top` 一直停在旧值。注入 `*{transition:none!important}` 之后立刻全部对齐。**同一个坑会以不同的面目反复出现：凡是「靠动画/过渡到达的状态」，在无头测试里都必须先关掉过渡再去量。**
- **改 UI 前先量出「改之前」的数字**：天气条的高度预算不是拍的 —— 先用 iframe 在 375 / 500 / 731 / 900 / 1280 / 1440 六个宽度下把 `getBoundingClientRect().height` 全量打印一遍，再拿实测值定阈值（40 / 74 / 100）。这样写出来的断言既不会松到没意义，也不会紧到下次改个文案就红。

## ⚠️ 已知限制

1. **房间基于公共服务 textdb.dev**：房间码即钥匙，任何拿到它的人都能读写，**请勿放敏感信息**；公共服务的保留策略与可用性不由本项目保证——重要内容请用「分享链接」或导出 JSON 留档
2. **活动是示例数据**（16 条内置），未接真实活动源；封面是用 CSS 渐变 + emoji 生成的占位图，没有真实照片
3. 距离为示例值，未接定位与真实通勤时间
4. 无账号体系：昵称仅在本机登记，换设备需重新填
5. 同步靠轮询（6 秒），不是 WebSocket 实时推送
6. **节假日是硬编码的 2026 年安排**（`HOLIDAYS` 常量，来源：国办发明电〔2025〕7号）：跨年后需要更新这张表；界面上标了来源，不会让人误以为能自动跟随
7. **「看过新手引导」只记在本机**（`localStorage` 的 `wcg.guided.v2`）：换浏览器、换设备、清空数据之后会再弹一次。这是「没有账号体系」的必然结果 —— 真要做成跟随账号，得先有后端
8. **图标是 24×24 网格上的通用几何造型**（房子 / 放大镜 / 心形 / 日历之类）：够用且风格统一，但谈不上什么识别度，需要的话可以整批换成一套原创图标
